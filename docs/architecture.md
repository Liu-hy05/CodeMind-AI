CodeMind AI 系统架构设计文档

## 1. 项目概述

CodeMind AI 是一个面向企业研发场景的智能代码理解与知识管理平台。

系统通过整合：

- 企业项目代码
- 接口文档
- 数据库设计
- 历史问题记录
- 企业知识文档

结合大语言模型（LLM）和知识检索增强生成技术（RAG），帮助开发人员快速理解项目，提高研发效率，降低重复沟通成本。

主要目标：

- 降低新成员理解项目的时间成本
- 减少开发人员重复查询和解释工作
- 提高代码维护和问题定位效率
- 利用 AI 辅助完成代码分析和知识问答

# 3. 项目模块结构设计


当前后端采用 Maven 多模块架构：

```
backend

├── pom.xml

├── codemind-common

├── codemind-user

├── codemind-knowledge

└── codemind-ai
```


模块职责：

| 模块               | 职责                           |
| ------------------ | ------------------------------ |
| codemind-common    | 公共组件、工具类、统一返回结构 |
| codemind-user      | 用户管理、认证、权限           |
| codemind-knowledge | 文件管理、知识库构建、文档检索 |
| codemind-ai        | 大模型调用、AI能力封装         |


---

# 4. 各模块职责设计


## 4.1 codemind-common


职责：

提供所有业务模块共享的公共能力。


主要包含：

- 通用返回对象
- 全局异常定义
- 公共工具类
- 系统常量


例如：

```
Result<T>

BusinessException

Constants
```


设计目的：

避免多个业务模块重复编写相同代码，提高代码复用性。


---

```
codemind-user
```

负责用户相关业务。


主要功能：

- 文件解析

# 5. 数据存储设计


## 5.1 MySQL


负责存储结构化业务数据。


存储内容：

- 用户信息
- 用户权限
- 文件元数据
- 聊天记录
- 系统配置


选择原因：

MySQL适合：

- 结构化数据
- 事务操作
- 关系查询


保证企业核心数据可靠保存。


---

# 5.2 Redis


负责缓存和高频访问数据。


存储内容：

- 用户登录Token
- 热点问题
- AI回答缓存
- 临时任务状态


选择原因：

Redis基于内存存储。

可以：

- 提高查询速度
- 降低数据库压力
- 提升系统响应能力


---

# 5.3 Milvus


负责向量数据存储。


存储：

- 文档向量
- 代码语义向量
- 历史问题向量


选择原因：

传统数据库只能进行关键词查询。

但是企业代码和文档需要：

- 语义理解
- 相似内容搜索
- 上下文关联


Milvus通过向量检索实现：

```
用户问题

↓

向量化

↓

相似度搜索

↓

返回相关知识
```

# 7. 为什么需要RAG知识增强


直接调用大模型存在问题。


## 7.1 模型幻觉问题


大模型可能生成：

- 不存在的代码
- 错误接口
- 错误业务逻辑


通过企业知识库：

让模型基于真实资料回答。


---

## 7.2 企业知识缺失


公共大模型不了解企业内部：

- 项目代码
- 数据库设计
- 接口文档
- 业务规则


通过RAG：

将企业私有知识提供给模型。


---

## 7.3 Token成本问题


如果直接将全部项目资料发送给模型：

会导致：

- Token消耗过高
- 调用成本增加
- 响应速度下降


RAG流程：

```
全部知识

↓

向量检索

↓

只发送相关内容

↓

降低Token消耗
```

# 8. 模块化设计原因


系统按照业务职责拆分：

```
User Service

Knowledge Service

AI Service
```


原因：


## 8.1 降低复杂度


不同业务拥有独立职责。

避免所有代码集中在一个巨大项目中。


---

## 8.2 提高维护效率


当功能出现问题：

可以快速定位对应模块。


例如：

用户问题：

```
codemind-user
```


知识库问题：

```
codemind-knowledge
```


AI问题：

```
codemind-ai
```


避免在大量代码中寻找问题。


---

# 10. 总结


CodeMind AI采用模块化架构设计：

通过：

- Spring Boot多模块工程
- MySQL结构化存储
- Redis缓存优化
- Milvus向量检索
- RAG知识增强
- LLM智能生成

构建面向企业研发场景的智能辅助平台。


系统当前重点解决：

> 企业项目知识分散，新成员理解困难，开发人员重复查询成本高的问题。


未来通过Agent能力进一步实现：

> 从AI问答向AI辅助研发自动化演进。
